# Session Folder Schema (draft)

Structural contract for a SessionFolder — one session's on-disk presence inside the journal.

## Folder layout

```
journal/YYYY/MM/DD/
  HHMM_<slug>/                     ← SessionFolder
    state.md                       ← session scope + Problems (continuously updated)
    transcript/                    ← per-turn raw log (hook-driven)
      index.json                   ← turn counter + metadata
      000_msg.md                   ← unindexed turn
      001_msg.md
      002_PromotionDecision.md     ← indexed turn (slug added by indexer)
      ...
    <any other files>              ← see "Other files" below
```

**SessionFolder name** — `HHMM_<slug>/`. `HHMM` is the start time of the session. `<slug>` is mutable via the MCP tool `rename_current_session(new_slug)`; on rename, MCP performs `mv` on the folder and updates the SessionStateFile.

## SessionID

A UUID generated by Claude Code at session start. Available in every hook's stdin payload as `session_id`. Also appears in the name of the Claude Code internal transcript file: `~/.claude/projects/<encoded-project-path>/<session_id>.jsonl` (this is the JSONL file referenced by `transcript_path` in hook payloads).

The SessionID is the key used to locate the SessionStateFile (`.claude/sessions/<session_id>.json`).

## Slug naming

Slugs (for SessionFolder and for per-turn files alike) follow the same rules as ObjectiveFolder slugs:
- `camelCase` or `snake_case`;
- forbidden characters: dashes, dots, any other splitting characters (they break double-click selection in chat and corrupt copy-paste).

## Transcript folder

`<SessionFolder>/transcript/` — raw log of the session, one file per turn.

### Per-turn file

Each turn is one file. Initial name: `NNN_msg.md` (where `NNN` is the turn index, zero-padded). After async indexing the file is renamed to `NNN_<slug>.md` (e.g., `002_PromotionDecision.md`).

File contents:

```markdown
## NNN <Title>                     ← H2; <Title> is added by the indexer

**User:**

<user message>

**Assistant:**

<assistant response>

**User (mid-flight):**

<message the user sent while the assistant was still working>

**Assistant:**

<continued response>
```

Notes:
- The file-level header is **H2** so that concatenating all turn files (`cat 000_*.md 001_*.md … > merged.md`) yields a clean H2-chaptered document.
- `User` / `Assistant` / `User (mid-flight)` are bold paragraph labels, not headers — keeps the visual hierarchy clean when merged.
- Before indexing the title is just `## NNN`; after indexing the title becomes `## NNN <Title>`.
- Multiple `**Assistant:**` / `**User (mid-flight):**` blocks may interleave within a single turn file when mid-flight messages arrive. They are emitted in chronological order, preserving the real conversation flow.

### Counter and metadata

`<SessionFolder>/transcript/index.json` — counter and per-turn metadata. Schema:

```json
{
  "next_index": 3,
  "turns": [
    {
      "index": 0,
      "slug": null,
      "file": "000_msg.md",
      "prompt_id": "<UUID of the turn-defining user prompt>",
      "started_at": "2026-05-21T14:18:41.743Z",
      "ended_at": "2026-05-21T14:18:53.094Z",
      "complete": true,
      "midflight_count": 0,
      "assistant_count": 1
    },
    {
      "index": 1,
      "slug": null,
      "file": "001_msg.md",
      "prompt_id": "<UUID>",
      "started_at": "…",
      "ended_at": "…",
      "complete": true,
      "midflight_count": 1,
      "assistant_count": 2
    },
    {
      "index": 2,
      "slug": "PromotionDecision",
      "file": "002_PromotionDecision.md",
      "prompt_id": "<UUID>",
      "started_at": "…",
      "ended_at": "…",
      "complete": true,
      "midflight_count": 0,
      "assistant_count": 1
    }
  ]
}
```

Per-turn fields:

- `prompt_id` — UUID of the user prompt that opens the turn. Used by the Stop hook to detect resumed chats (see *Hook flow* below).
- `started_at` / `ended_at` — ISO timestamps of the first user message and the last assistant message in the turn.
- `complete` — `true` once the assistant has produced its final response for the turn.
- `midflight_count` — number of mid-flight user messages within the turn (each rendered as a `**User (mid-flight):**` block).
- `assistant_count` — number of assistant message blocks within the turn.

`next_index` is `len(turns)` — recomputed and written by the Stop hook on each fire as turns are reconciled from the JSONL.

### Hook flow

A single Stop hook drives transcript persistence (see `cockpit/specs/architecture.md` §4). On each fire:

1. The hook reads `transcript_path` from the payload, parses the JSONL, and groups entries into turns by `prompt_id`.
2. For each turn, it computes the desired `NNN_*.md` body and reconciles against the on-disk file.
3. The hook writes `index.json` atomically (temp + rename) with the updated turns.

Bootstrap (first fire of a new SessionFolder): the hook creates `transcript/`, writes an initial empty `index.json`, derives the SessionFolder name from the first user prompt's timestamp (`HHMM_session/`), and writes the SessionStateFile.

A separate async indexer (run via `claude -p` against `instructions/subagents/transcript_indexer.md`) reads each `NNN_msg.md`, generates a slug + title, renames the file to `NNN_<slug>.md`, and writes the `slug` field into `index.json`. The indexer is **out-of-band** from the Stop hook — both can safely run on the same SessionFolder; concurrency is handled via slug-based race protection in the hook (see `architecture.md` §4 → *Concurrency model*).

## SessionStateFile

Lives outside the SessionFolder, in `<ContextFolder>/.claude/sessions/<session_id>.json`. A minimal pointer from a Claude Code `session_id` to the SessionFolder it owns:

```json
{
  "session_folder": "/abs/path/to/journal/YYYY/MM/DD/HHMM_slug/",
  "first_prompt_id": "<UUID of turn 0>"
}
```

Fields:

- `session_folder` — absolute path to the SessionFolder for this `session_id`.
- `first_prompt_id` — `prompt_id` of the first user turn. Used on resumed chats: Claude Code assigns a *new* `session_id` when a conversation resumes, but the first prompt's UUID is stable. On bootstrap, the Stop hook scans existing SessionFolders' `index.json` for a matching `turns[0].prompt_id`; if found, it reuses that folder instead of creating a duplicate.

Derivable elsewhere (so not stored here):

- `session_id` is the filename itself (`<session_id>.json`).
- `started_at` lives in `index.json` as `turns[0].started_at` and in the JSONL.

Usage flow:

- The Stop hook self-bootstraps the SessionStateFile on first fire (see `architecture.md` §4 → *Lifecycle*).
- The Stop hook reads it on subsequent fires to locate the SessionFolder.
- MCP `rename_current_session` updates `session_folder` after `mv` on the folder.

## state.md — session scope and Problems

`<SessionFolder>/state.md` — the session's working state, continuously updated by the agent as the chat evolves. It exists for two reasons:

1. **Reconstruction.** Re-computing the live list of Problems and their sub-entities by scanning every turn file of a long chat is expensive and error-prone, especially when items are revised often. A serialized snapshot is cheaper to read and reason about.
2. **Session scope.** Which Objectives are in scope for this session, and at what engagement mode, lives nowhere else — neither the Objective file nor the transcript captures this naturally.

### File structure

```markdown
# Session state

## Input
*(optional)* — external inputs the session consumes (briefs, links, ТЗ paths).

## Scope
- OBJ001 [work]            — full work session
- OBJ005 [what|why]        — interview mode, refining formulation
- OBJ012 [draft]           — just drafting, may go to backlog

## Problems
- P1 ParallelChatTracking (open)
  - P1.I01 ScopeBoundary (open) — is this one thing or two?
  - P1.S02 SplitProposal (canceled) — user declined: prefers different split
- P3 SaveTimingQuestion (draft)
```

### Sections

- **`## Input`** — *(optional)* — references to external inputs the session consumes. Omit if empty.
- **`## Scope`** — list of Objectives in session scope, with engagement mode in brackets. Engagement modes: `draft` / `what|why` / `how` / `work`. Modes are described in `domain-model.md` §2.3.
- **`## Problems`** — list of Problems (chat-only, session-scoped) with their sub-entities nested as indented bullets. Each line: `<code> <Slug> (<state>) — <short note>`.

### Lifecycle

- The agent updates `state.md` continuously as Problems are flagged / triaged / canceled, sub-entities created / closed / canceled, and the session scope shifts.
- `canceled` Problems and `canceled` sub-entities **may be removed** from `state.md` to keep the context lean. Their history remains recoverable from the `transcript/` (and through change-log lines emitted at the moment of state change).
- At session end, `state.md` is left as-is — it is the session's last live snapshot. Untriaged Problems remaining there are lost (per the Problem's ephemeral semantics).

### Why this is not the source of truth

`state.md` is a **derived cache**, not the canonical record:
- For Objective state and sub-entities — the OBJ folder is the source of truth (`schemas/obj_folder.md`).
- For "what was said in the session" — the `transcript/` is the source of truth.
- For Problems — the chat itself, supplemented by change-log lines, is the source of truth; `state.md` is the live index.

## Other files

The SessionFolder is otherwise open — beyond the structured files above, any working artifacts produced or collected during the session may live as siblings. Typical examples:

- temporary scripts and intermediate generations;
- chats imported from external surfaces (e.g., `claude.ai` web exports, ChatGPT transcripts, Gemini logs);
- ad-hoc notes the user drops into the session.

These files are not promoted to git or to OBJ folders automatically — they remain in the SessionFolder unless the user explicitly moves them.
